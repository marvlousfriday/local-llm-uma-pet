# 04 · 添加新角色：从 UmaViewer 录制到桌宠跑起来

> 目标：给 DesktopGremlin v4.0 增加一位新马娘（示例：美丽周日 / MarvelousSunday），包含雪碧图、动作配音、图标、人设与朗读音色，并做到切换角色时自动适配。
>
> 本仓库**不收录角色素材本身**：一位角色的雪碧图约 55MB、配音约 1.5MB，且属于 Cygames 游戏资源的派生内容。仓库提供工具链、模板与方法，素材在你本机的游戏数据上生成。

---

## 1. 角色是怎么被找到的

根目录 `config.txt` 的 `START_CHAR` 是唯一开关，它同时被拼成四条路径：

| 用途 | 路径 | 源码位置 |
|---|---|---|
| 雪碧图 | `SpriteSheet/Gremlins/<名>/<子目录>/<动作>.png` | `SpriteManager.LoadSprite` |
| 帧数 / 尺寸 | `SpriteSheet/Gremlins/<名>/config.txt` | `FrameCounts.LoadConfigChar` |
| 动作音效 | `Sounds/<名>/<动作>.wav` | `MediaManager.PlaySound` |
| 托盘图标 | `Gremlins/<名>/Misc/<名>.ico` | `ConfigManager.SetupTrayIcon` |

v4.0 源码里**没有任何角色名分支**（早期 readme 里 "each Uma is unique in terms of code" 是老版本遗留说法，已过时）。`Options.exe` 扫描 `Gremlins/` 下的子目录动态生成角色列表——新建一个目录就会自动出现在可选列表里，不需要改 exe。

所以：**目录名 = 角色名 = START_CHAR**，三者必须一致。建议纯 ASCII、无空格、无中文。

---

## 2. 目录结构

```
<PET_DIR>/
  config.txt                       START_CHAR = <Name>
  persona_<Name>.txt               该角色的人设（见第 9 节）
  SpriteSheet/Gremlins/<Name>/
    Actions/   idle intro outro click grab hover sleep runIdle pat
    Run/       runUp runDown runLeft runRight upLeft upRight downLeft downRight
    Walk/      walkUp walkDown walkLeft walkRight
    Emotes/    emote1 emote2 emote3 emote4
    Misc/      <Name>.ico
    config.txt
  Sounds/<Name>/
    intro.wav outro.wav grab.wav hover.wav emote1-4.wav
    sleep.wav run.wav mambo.wav food.wav
```

`eat.wav` 是全局的，放在 `Sounds/Misc/`，所有角色共用。**没用到的动作可以不放文件**：`MediaManager` 找不到文件直接返回，状态机会静默回落到 Idle，不崩也不弹框。

例外：`Actions/outro.png` **不要删**。源码里只有 Outro 播到 `currentFrame == 0` 才 `Application.Shutdown()`；图片缺失时 `SpriteManager` 返回 `-1`，托盘的「Stylish Close」会永远关不掉程序。没有录这个动作时，用新角色的 idle 帧填一张同尺寸的 outro 即可。

## 3. 角色 config.txt 规格

参考 `pet/sprite-tools/config.example.txt`：

```
WIDTH=325
HEIGHT=325
COLUMN=10
SCALE=1.0        // 显示缩放，XAML 基准是 300x300
IDLE=340         // 各动作帧数，键名见 FrameCounts.cs 的 switch
WALKDOWN=30
RUNUP=18
...
```

每张 png 是 **10 列网格雪碧图**，宽度 = `WIDTH * COLUMN`，高度 = `HEIGHT` 的整数倍。裁切公式：

```
x = (frame % COLUMN) * WIDTH
y = (frame / COLUMN) * HEIGHT
```

硬约束：**帧数 ≤ (图宽 / WIDTH) × (图高 / HEIGHT)**。超过不会崩，只会永远卡在最后一帧（上游自带的 GoldShip 配置自己就超了）。改素材后务必重算帧数。

显示链路上还有两层缩放：`SpriteImage` 基准 300×300 → 乘 `SCALE` → 实际显示 270~330px。想更锐可以把 `SCALE` 设成 `1.0`，或让素材格改成 300 做 1:1。

## 4. 录制素材（UmaViewer）

| 设置 | 值 | 说明 |
|---|---|---|
| 模型视角 | **chibi / Q 版** | 正常比例 3D 模型与桌宠 Q 版 2D 画风不搭 |
| Width × Height | **1024 × 1024** | 2x 超采样，降到 325 格后边缘最干净 |
| Transparent | **勾选** | 得到 8bit alpha，不用抠白底 |
| Sequence fps | **30** | 桌宠 `SPRITE_FRAMERATE=30`；面板默认 120 会让动作慢 4 倍 |
| 按钮 | **Record PNG Sequence** | 真彩色 + 8bit alpha；GIF 只有 256 色和 0/255 二值透明 |

实测边缘锐度：512 GIF **4.53** → 1024 PNG 序列 **6.73**（官方 2D 平涂素材 5.85）。1536/2048 没有收益——每帧最终仍塞进 325 格，只是文件大几倍。

录制完**立刻把 `UmaViewer_<时间戳>/` 文件夹改名成动作名**（`idle`、`walkDown`…）。不改脚本会忽略它，攒一堆时间戳目录你事后也分不清谁是谁。

所有动作必须**同一分辨率、同一相机距离**：转换器用一张全局裁切框，混用会错位。

详细命名规则与参数说明见 `pet/sprite-tools/NAMES.txt`。

## 5. 动画名怎么对上桌宠动作

UmaViewer 的 Animation 面板显示的是**游戏内部 AnimationClip 名**（`Idle01`、`RunSlowA`、`Garden_01001_0101_loop` 这类英文罗马字 ID），没有中文/日文本地化，也没有语言切换。`Config.json > Language`（0=En / 1=Jp）只影响**角色名**。

别找翻译，用**帧数当指纹**——面板进度会显示总帧数，录制器也是按 `clipLength × frameRate` 抓帧：

| 动作 | 中文 | 帧数 |
|---|---|---|
| `idle` | 待机 | 369 |
| `click` | 点击 | 134 |
| `sleep` | 睡觉 | 79 |
| `runIdle` | 跑待机 | 61 |
| `intro` | 登场 | 50 |
| `hover` | 悬停 | 42 |
| `grab` | 抓取 | 5 |
| `walk*` | 走 四方向 | 各 30 |
| `run*` | 跑 八方向 | 各 18 |

8 个跑、4 个走帧数相同，方向靠首帧姿势（正 / 背 / 侧）区分，或者干脆照上次顺序重录。

## 6. 转成雪碧图

```bash
python pet/sprite-tools/gif_to_sheet.py <录制目录> <角色目录> --no-fill
```

改好 `pet/sprite-tools/build_sheets.bat` 顶部三个占位路径后双击也行。

脚本做的事：

- **流式读帧**：1024px、369 帧的序列一次性载入要 1.5GB，逐帧处理则内存平稳
- **全局裁切框**：扫描所有录制的采样帧取 alpha 包围盒并集，所有动作共用，避免帧间角色忽大忽小
- **放得下就 1:1 贴，不重采样**；放不下才 LANCZOS 降采样
- **轮廓外 3px 颜色外扩**：调色板 GIF 的透明区 RGB 是纯黑，任何插值都会把黑混进可见边缘形成灰雾
- 轻锐化 `UnsharpMask(0.7, 110%, 2)`；左右动作自动镜像；单张静图 → 12 帧呼吸循环
- 自动改 `config.txt` 里被重建动作的帧数
- `--no-fill` 保留未录动作的占位图；去掉它则用新角色 idle 帧按原尺寸填满（推荐，避免串出别的角色）

画质上最容易踩的三个坑：不必要的 LANCZOS 缩放、透明区纯黑、逐帧自动裁切。**源素材其实往往是锐的，糊是转换引入的。**

## 7. 动作配音

音色来自本地 VITS（`tts/tts_server.py` 那套），模型库 `gouhuo/Umamusume_Vits_models` 下每位角色一个目录（`G_latest.pth` 约 151.5MB + `config.json`）。下载到 `<UMAVITS_DIR>/models/<角色名>/`：

```
https://hf-mirror.com/gouhuo/Umamusume_Vits_models/resolve/main/<Char>/G_latest.pth
https://hf-mirror.com/gouhuo/Umamusume_Vits_models/resolve/main/<Char>/config.json
```

下载注意：**直连可用**（curl 加 `--noproxy '*'`），走系统代理常返回 503/521；HuggingFace 官方站直连通常不通。

然后 `python pet/sprite-tools/make_voice.py`（先改脚本顶部两个路径常量，或设 `UMAVITS_DIR` / `PET_SOUNDS_DIR` 环境变量）。它会另起 **9881** 端口跑 `--char <角色>`，不碰桌宠的 9880，批量 POST `/tts` 生成 wav。

「哪个动作配哪句」是**硬编码在桌宠 C# 源码里**的，不是翻译表：

| wav | 触发 | wav | 触发 |
|---|---|---|---|
| `intro` | 启动 | `outro` | 托盘 Stylish Close |
| `grab` | 左键抓取 | `hover` | 悬停（5 秒节流） |
| `emote1-4` | 热点 / 随机表情 | `sleep` | 入睡 |
| `run` | 跑步 | `mambo` | 随机舞蹈 |
| `food` | 投喂 | `eat` | 全局 `Sounds/Misc/`，别放角色目录 |

`wake / pat / click / spawn` 在 v4.0 源码里**从未被调用**，是死文件。

VITS 模型**只吃日语**，中文文本会得到静音。台词按角色口癖写短句即可（模板在 `make_voice.py` 的 `LINES`）。

## 8. 托盘图标

`Misc/<名>.ico` 必须是**真 ICO**——把截图 PNG 直接改后缀，桌宠的 `new Icon(path)` 会抛异常导致启动崩溃。

做法：按 alpha 包围盒裁掉四周透明、补约 6% 透明边距成正方形，再用 Pillow 保存 6 个尺寸：

```python
canvas.save(path, format='ICO',
            sizes=[(16,16),(32,32),(48,48),(64,64),(128,128),(256,256)])
```

竖版截图如果不裁包围盒，角色在 16×16 托盘里会缩成一个点（实测覆盖率 9.1% → 裁后 27.7%）。ICO 规范里 256 项的宽高字节记作 `0`，是合法的。

另外：别把源 PNG 留在会被 `gif_to_sheet.py` 的 `fill_remaining()` 扫到的位置——脚本已限制只处理 `Actions/Run/Walk/Emotes` 四个目录。

## 9. 人设与朗读音色按角色自动切换

不这么做的话，每次换角色都要手改 `persona.txt` 和 TTS 音色。两处 C# 改动（完整文件见 `pet/csharp/`）：

**`ChatWindow.xaml.cs` — 按角色挑人设**

```csharp
string dir = AppDomain.CurrentDomain.BaseDirectory;
string ch = Settings.StartingChar;
string path = Path.Combine(dir, "persona_" + ch + ".txt");
if (string.IsNullOrEmpty(ch) || !File.Exists(path))
    path = Path.Combine(dir, "persona.txt");   // 兜底
```

人设文件必须保留 `[中]` / `[日]` 两行格式约定，否则 `LoadPersona()` 会整个忽略文件，气泡显示但不朗读。模板见 `pet/personas/`。

**`TtsLauncher.cs` — 启动时传音色**

```csharp
" --char \"" + TtsModelName(script) + "\"" +
```

`TtsModelName()` 把角色目录名映射到模型目录名（历史遗留的 `Doto → MeishoDoto`），模型目录不存在则记录日志并回退，避免服务起不来。

**一个很隐蔽的坑**：`Options.exe` 保存配置会把自定义项冲掉，导致 `TTS_ENABLED / TTS_PYTHON / TTS_SCRIPT / TTS_IDLE` 四项消失。`ChatWindow.Speak()` 有 `if (!Settings.TtsEnabled) return;`，`TtsLauncher` 又要求 py/script 非空——**结果不是音色不对，是聊天朗读整条链路哑掉**。切完角色后检查这四项还在不在。

改完重编译（`pet/build.bat`，Roslyn），之后：

1. `Options.exe` 改 `START_CHAR`（或直接改 `config.txt`）
2. 重启桌宠

人设与音色自动跟着变。新增角色只需加 `persona_<名>.txt` + `umavits/models/<同名>/`；缺任一个都只会回退，不会崩。

## 10. 验收清单

| 检查 | 方法 |
|---|---|
| 角色出现在列表 | `Options.exe` 能看到新目录名 |
| 帧数合法 | 每个动作 `帧数 ≤ (图宽/WIDTH)×(图高/HEIGHT)` |
| 无别的角色残留 | 对占位图做 MD5 比对；wav 采样率普查 |
| 图标合法 | ICONDIR `reserved=0 / type=1`，6 个正方形尺寸 |
| 人设生效 | `persona_<名>.txt` 含 `[中]` 与 `[日]` |
| 音色生效 | 启动后看 `/health` 的 `model` 字段 |
| 退出可用 | 托盘 Stylish Close 能关掉程序（依赖 `outro.png`） |

## 11. 坑速查

| 症状 | 原因 |
|---|---|
| 桌宠启动即崩，无提示 | `Misc/<名>.ico` 是改了后缀的 PNG |
| 角色动起来忽大忽小 | 逐帧自动裁切，没用全局裁切框 |
| 边缘一圈灰雾 / 发虚 | 不必要的 LANCZOS 缩放 + 透明区纯黑被插值 |
| 动作慢 4 倍、磁盘暴涨 | `Sequence fps` 用了面板默认 120 |
| 换角色后声音还是别人 | `--char` 没传，或模型目录名对不上 |
| 聊天完全不朗读 | `TTS_*` 四项被 `Options.exe` 冲掉 |
| 托盘退出关不掉程序 | 删了 `Actions/outro.png` |
| 随机表情闪出别的角色 | 占位图没清，或没去掉 `--no-fill` |
| 录制目录被脚本忽略 | 文件夹名不是动作名（`UmaViewer_<时间戳>`） |

## 限制

- 角色素材不入库：体积大，且为游戏资源派生内容，版权归 Cygames
- 3D Q 版录制再怎么优化，也达不到官方 2D 平涂硬描边的锐利度
- 动画名没有本地化映射，靠帧数指纹辨认
- 缺动作时桌宠静默回落 Idle，不会报错但也不会有该动作
