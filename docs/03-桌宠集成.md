# 03 · 桌宠集成：给 DesktopGremlin 装上嘴和大脑

> 目标：在 [Desktop_Gremlin v4.0](https://github.com/Kritzkingvoid/Desktop_Gremlin) 的 WPF 桌宠上，右键弹出一个能聊天的气泡，回复带日语朗读。
>
> 上游是 C# / .NET Framework 4.8 / WPF 项目，本仓库提供**覆盖式补丁**：把 `pet/csharp/` 里的文件丢进上游 `Desktop_Gremlin/` 目录，再按本文手动改三处，即可编译。

---

## 两种实现

| 版本 | 入口 | 原理 | 状态 |
|---|---|---|---|
| **C# 版（推荐）** | 右键桌宠 → 气泡 | 改上游源码，原生 WPF 窗口 | 已编译部署 |
| Python 外挂（备用） | `start-pet-chat.bat` | 枚举窗口找桌宠矩形，Tk 弹窗 | 可用，气泡不跟随 |

C# 版是正解：气泡能跟随角色、能访问精灵图做头像、能管 TTS 生命周期。Python 版只是"不改源码也能玩"的妥协。

## C# 版：五处改动

### 1. 新增文件（直接覆盖）

```
pet/csharp/OllamaClient.cs     →  Desktop_Gremlin/
pet/csharp/TtsLauncher.cs      →  Desktop_Gremlin/
pet/csharp/ChatWindow.xaml     →  Desktop_Gremlin/
pet/csharp/ChatWindow.xaml.cs  →  Desktop_Gremlin/
```

### 2. 工程文件 `Desktop_Gremlin.csproj`

加 `Compile` 条目（`ChatWindow.xaml.cs` 要挂 `DependentUpon`）：

```xml
<Compile Include="OllamaClient.cs" />
<Compile Include="TtsLauncher.cs" />
<Compile Include="ChatWindow.xaml.cs">
  <DependentUpon>ChatWindow.xaml</DependentUpon>
</Compile>
```

加 `Page` 条目：

```xml
<Page Include="ChatWindow.xaml">
```

### 3. 右键入口 `MainWindow.xaml` / `MainWindow.xaml.cs`

XAML 里 `SpriteImage` 加事件（**别加在 Grid 上**，图片四周是透明的，加在 Grid 上手感会很怪）：

```xml
<Image Name="SpriteImage" ... MouseRightButtonDown="SpriteImage_RightButtonDown" />
```

代码后置加字段和方法：

```csharp
private ChatWindow _chatWindow;

private void SpriteImage_RightButtonDown(object sender, MouseButtonEventArgs e)
{
    e.Handled = true;                       // 不吞掉会触发拖动
    if (_chatWindow == null || !_chatWindow.IsLoaded)
    {
        _chatWindow = new ChatWindow();
        _chatWindow.Owner = this;           // Owner 用于跟随定位
    }
    _chatWindow.PositionNear(this);
    _chatWindow.Show();
    _chatWindow.Activate();
}
```

`e.Handled = true` 是必须的——上游左键是"抓取拖动"，右键不标记已处理会连带触发拖动逻辑。

### 4. TTS 启停

`MainWindow` 构造函数末尾（**必须等配置加载完**，所以不能放 `App` 里）：

```csharp
try { TtsLauncher.EnsureRunning(); } catch { }
```

`App.xaml.cs` 注册退出清理：

```csharp
public App() { ... this.Exit += App_Exit; }

private void App_Exit(object sender, ExitEventArgs e)
{
    try { DesktopGremlin.TtsLauncher.Stop(); } catch { }
}
```

### 5. 配置项 `ConfigManager.cs` + `SpriteVariables.cs`

`SpriteVariables.cs` 加四个静态属性（`TtsEnabled` 默认 `false`，`TtsIdle` 默认 1800）：

```csharp
public static bool   TtsEnabled { get; set; } = false;
public static string TtsPython  { get; set; } = "";
public static string TtsScript  { get; set; } = "";
public static int    TtsIdle    { get; set; } = 1800;
```

`ConfigManager.cs` 的解析表加四行：

```csharp
["TTS_ENABLED"] = val => { if (bool.TryParse(val, out bool v)) Settings.TtsEnabled = v; },
["TTS_PYTHON"]  = val => Settings.TtsPython = val.Trim().Trim('"'),
["TTS_SCRIPT"]  = val => Settings.TtsScript = val.Trim().Trim('"'),
["TTS_IDLE"]    = val => { if (int.TryParse(val, out int v)) Settings.TtsIdle = v; },
```

`config.txt`：

```
TTS_ENABLED = true
TTS_PYTHON  = <项目根>\venv\Scripts\pythonw.exe
TTS_SCRIPT  = <项目根>\tts_server.py
```

两项留空则不自动启停。**服务已经在跑时只探测不接管**，退出时也不会杀别人的进程。

## 编译

```bat
build.bat
```

产物：`src40/Desktop_Gremlin/Desktop_Gremlin/bin/Release/DesktopGremlin.exe`

### 坑 1：31 个 MSB3030 + 228 个 CS 错误

两个坑一起来，很容易以为项目本身是坏的。

**CS 错误（228 个）**：`%WINDIR%\Microsoft.NET\Framework64\v4.0.30319\` 里那个 `csc.exe` 是 **C# 5**，而项目源码用了属性初始化器、`$"..."` 插值等 C# 6+ 语法。直接编会报：

```
CS1519: 类、结构或接口成员声明中的标记“=”无效
CS1056: 意外字符“$”
```

解法：`/p:CscToolPath` 指向 NuGet 包 `Microsoft.Net.Compilers 3.11.0` 的 Roslyn 编译器。`build.bat` 已经配好（`tools/roslyn/tools/csc.exe`，11MB，免安装免管理员）。

**MSB3030（31 个）**：原 csproj 列了 85 个 `<Content Include="SpriteSheet\...">` 要复制到输出目录，但 GitHub 仓库里只有 28 个素材样例——完整素材在 release zip 里。

这些 PNG 是**运行时按相对路径读取**的（`<Resource Include>` 数量为 0），编译根本不需要。删掉多余的 Content 条目即可，原文件备份为 `Desktop_Gremlin.csproj.bak`。

> 换句话说：**编译不需要素材，运行需要**。素材从 Desktop_Gremlin 的 release zip 拿。

### 坑 2：系统代理劫持本地请求

Clash 之类的工具会设 `HTTP_PROXY`，而 `NO_PROXY` 为空——`127.0.0.1` 也被代理，请求 11434 返回 **502**，而 Ollama 明明活着。

C# 端一行解决：

```csharp
req.Proxy = null;
```

Python 端：

```python
opener = urllib.request.build_opener(urllib.request.ProxyHandler({}))
```

排查命令（注意 `--noproxy`）：

```bash
curl --noproxy '*' http://127.0.0.1:11434/api/version
```

## 气泡 UI

### 折叠 / 展开与底部锚定

默认**折叠态**（高 190）：头部 + 最后一条回复 + 输入框，挂在桌面上不挡事。点头部右上角 **▲** 展开到 440px，显示完整历史。

关键在**底部锚定**：高度变化时窗口向上长高，尾巴始终指向桌宠，不会盖住角色。

```csharp
// SizeToContent 模式下 Height 是 NaN，必须用 ActualHeight
double myH = ActualHeight > 0 ? ActualHeight : 190;

// SizeChanged 里保持底边不动
_anchorBottom = Top + ActualHeight;
```

踩过的坑：直接用 `Height` 定位，展开瞬间算出来是 `NaN`，窗口跳到屏幕左上角。

### 跟随角色

`DispatcherTimer` 200ms 轮询 `Owner.Left/Top/ActualWidth`，角色走动时气泡跟着平移。角色靠边时 `ClampToScreen()` 把气泡夹在 `WorkingArea` 内。

### 头像自动裁切

气泡左上角的头像从当前角色 `idle.png` **第一格自动裁切**：按 alpha 通道找内容边界，适配不同角色的站位差异。失败回退显示「马」字。

写死裁切框必翻车——不同角色的精灵图里，人物在格子中的位置和大小都不一样。

## 双语输出

这是整个项目最实用的一招：**中文给人看，日语给耳朵听**。

中文 TTS 音色普遍难听，日语 VITS 说中文又很怪。解法是让模型输出两行：

```
[中] 今天训练辛苦了，要喝点蜂蜜特饮吗？
[日] 今日のトレーニング、お疲れさま。蜂蜜ドリンクでもどう？
```

`ChatWindow` 解析后：`[中]` 行进气泡，`[日]` 行送 `/tts`。

人设提示词（`ChatWindow.xaml.cs` 顶部常量）必须写清这个格式约定：

```
第一行以 [中] 开头，写中文回答，不超过 30 字。
第二行以 [日] 开头，写这句中文对应的日语口语说法，像动画台词，不超过 30 字。
```

两个细节：

- **人设文件里没有 `[中]`/`[日]` 就整段忽略**——宁可不出声，也不要念一段格式错误的文本
- 模型偶尔会漏掉 `[日]` 行，解析时做兜底（没日文就只显示不出声），不要让它抛异常把整个气泡卡住

## Python 外挂版

`pet/pet_chat.py`，不改上游任何源码：

```bat
start-pet-chat.bat
```

原理：`EnumWindows` 找 `desktopgremlin.exe` 的窗口矩形 → 轮询鼠标左键 → 落在矩形内就弹 Tk 气泡。

| 已知限制 | 说明 |
|---|---|
| 气泡不跟随 | 桌宠跑走后位置不更新 |
| 透明区域误判 | 按矩形判断，不认透明像素（点到角色周围的空白也会弹） |
| 需手动启动 | 自启就把 bat 快捷方式丢进 `shell:startup` |
| DPI 缩放 | 必须 `SetProcessDpiAwareness(2)`，否则高分屏坐标全错 |

配置在 `pet_chat.py` 顶部常量区：`MODEL` / `THINK` / `SYSTEM_PROMPT` / `PET_EXE` / `NUM_PREDICT`。

## 启动顺序

**只启动桌宠就行。**

```
DesktopGremlin.exe
  └─ MainWindow ctor → TtsLauncher.EnsureRunning()
       ├─ Ping(9880) 通 → 不接管
       └─ 不通 → 拉起 pythonw tts_server.py --port 9880 --idle 600 --parent-pid <自身PID>
```

退出时 `App_Exit` → `taskkill /PID <tts> /T /F`。

TTS 没起来时聊天照常工作，只是不出声（静默跳过，不报错）。

## 其它坑

| 现象 | 原因 |
|---|---|
| 气泡显示「[出错] 无法连接」 | Ollama 服务没起，`curl --noproxy '*' http://127.0.0.1:11434/api/version` 确认 |
| 第一次回复很慢 | 模型冷加载 8–10 秒（6.6GB 从磁盘读进显存） |
| 答非所问 / 说了不该说的 | `Model` 常量和 `ollama list` 里的名字不一致，请求落到了别的模型 |
| 气泡卡在屏幕外 | 多显示器拔掉后 `WorkingArea` 变了，重启桌宠即可 |
| 改了配置不生效 | `config.txt` 在 exe 同目录，不是源码目录 |
